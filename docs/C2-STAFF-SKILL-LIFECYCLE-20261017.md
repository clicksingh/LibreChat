## C2 fix: never return stale or cross-resource cached skill files

Before this change, primeSkillFiles reused every existing persisted codeEnvRef if a single object within each storage_session_id was fresh. That check did not assert ref.kind, ref.id or ref.version matches the currently loaded skill. A body-only SKILL.md edit bumps version without necessarily clearing a pre-existing bundled-file codeEnvRef. Consequently a newly revised skill body could be paired with previous revision supporting files. Also one deleted object could be overlooked if another object in the same storage session remained readable.

The C2 source change in packages/api/src/agents/skillFiles.ts requires every bundled-file cache ref to have kind=skill, id exactly current skill._id, version equal current skill.version and nonempty file/storage IDs. If any ref is wrong, the **whole bundle** must be freshly uploaded as kind=skill, correct id and current version. For valid refs, getSessionInfo is called for every distinct (storage_session_id,file_id) object rather than once per storage session; missing/deleted objects invalidate the cache. If safe reupload fails, primeSkillFiles returns null without passing stale references to the model. The fresh upload includes SKILL.md and always tags infrastructure read_only=true. No privilege broadening or database schema change.

Added packages/api/src/agents/skillFiles.spec.ts regressions for stale/future revision, wrong skill id, wrong kind, missing file/storage IDs, partially stale same-session bundles, deleted file with healthy sibling in same session, refresh failure, and current-version cache reuse. All are isolated synthetic mocks with no real customer/storage access.
